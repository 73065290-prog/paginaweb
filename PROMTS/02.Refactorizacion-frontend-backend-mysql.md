Quiero reorganizar la arquitectura de mi sistema Mass Online / SGC-Mass para separar claramente el **FRONTEND** del **BACKEND**, implementar un backend modular en PHP nativo y agregar persistencia real mediante MySQL/MariaDB.

Antes de modificar cualquier archivo, analiza todo el código fuente disponible en el proyecto local. Revisa su arquitectura, rutas, dependencias entre archivos, lógica de negocio, sesiones, formularios, autenticación, datos y pruebas existentes.

Conserva las tecnologías actuales:

- Backend: PHP nativo, compatible con PHP 8.1 o superior.

## 4. Separación del frontend

Traslada las vistas actuales de `cliente_interfaces/` y las vistas de `admin/` a `frontend/views/`, agrupándolas por módulo y conservando sus funcionalidades.

El frontend debe encargarse de:

- Mostrar el catálogo de productos y sus categorías.
- Mostrar fichas de productos.
- Gestionar la interfaz visual del carrito.
- Presentar el proceso de checkout.
- Mostrar la confirmación y el seguimiento de pedidos.
- Mostrar el inicio de sesión y el panel administrativo.
- Presentar la gestión de productos, inventario y pedidos.
- Contener los archivos CSS, JavaScript e imágenes de la interfaz.

Las vistas PHP pueden conservarse como plantillas del lado del servidor. Sin embargo, no deben contener consultas SQL ni implementar directamente reglas de negocio.

Centraliza los layouts, encabezados, pies de página y componentes compartidos cuando sea conveniente, evitando duplicaciones innecesarias.

Mueve los recursos de `assets/` a `frontend/assets/` y actualiza cuidadosamente todas sus referencias.

No cambies el diseño visual existente ni elimines funcionalidades durante la reorganización.

## 5. Implementación y separación del backend

Distribuye la lógica del sistema en los siguientes componentes:

**Config:** configuración de la conexión con MySQL y parámetros de la aplicación.

**Controllers:** recepción de solicitudes, validación inicial de parámetros y coordinación de las respuestas.

**Models:** representación de las entidades del sistema.

**Repositories:** consultas SQL y operaciones de lectura y escritura en la base de datos.

**Services:** reglas de negocio para productos, inventario, carrito, pedidos, descuentos y operaciones administrativas.

**Middleware:** controles de autenticación, permisos y protección de las solicitudes cuando corresponda.

**Validators:** validación de formularios y datos recibidos.

**Routes:** organización de las rutas de la aplicación y de los endpoints que sean necesarios.

**Bootstrap:** inicialización común del backend, carga de configuración y dependencias internas.

Evita colocar toda la lógica en un único archivo PHP. Cada componente debe tener una responsabilidad clara.

Cuando el frontend necesite operaciones asíncronas, crea endpoints que intercambien JSON y consúmelos desde JavaScript. Para los formularios existentes, conserva el flujo tradicional de PHP cuando sea más sencillo y seguro; no conviertas todas las páginas a una aplicación de una sola página sin necesidad.

## 6. Incorporación de MySQL/MariaDB

Actualmente, el proyecto utiliza datos de demostración en `includes/data.php` y estado de sesión. Necesito evolucionar hacia una base de datos real.

Primero, revisa todos los datos y las reglas existentes. Después, diseña e implementa `database/schema.sql` y `database/seed.sql`.

Incluye las tablas que realmente necesite el sistema, considerando al menos:

- Categorías.
- Productos.
- Usuarios y roles.
- Tiendas.
- Inventario por tienda.
- Cupones y descuentos.
- Pedidos.
- Detalles de cada pedido.

Define claves primarias, claves foráneas, restricciones e índices adecuados para las relaciones identificadas.

Migra los datos iniciales del catálogo y demás información necesaria desde las estructuras actuales hacia el script de carga inicial, conservando los valores y las reglas de negocio existentes.

Implementa las operaciones de acceso a la base de datos utilizando PDO y consultas preparadas. No construyas consultas SQL concatenando directamente datos proporcionados por los usuarios.

La configuración de conexión debe mantenerse fuera de los archivos públicos y no debe incluir contraseñas reales dentro del repositorio. Proporciona un ejemplo de configuración y documenta cómo configurarla localmente en XAMPP.

No elimines los datos de demostración ni el sistema anterior hasta comprobar que la nueva implementación funciona y que los datos necesarios han sido migrados correctamente.
