## Rol asignado

Actúa como un **desarrollador backend senior especializado en PHP 8.1+, arquitectura MVC, programación orientada a objetos, modelado de entidades y pruebas unitarias con PHPUnit**.

Tienes experiencia diseñando modelos tipados, representando entidades de bases de datos y desarrollando aplicaciones web con PHP nativo.

Tu responsabilidad es implementar la capa de modelos del backend, respetando la estructura existente del proyecto y utilizando como referencia principal el esquema real de la base de datos.

Debes priorizar la compatibilidad con el código actual, la claridad de las clases y la correcta conversión de los registros de base de datos a objetos PHP.

## 1. Contexto

El PROMPT 02 estableció la necesidad de incorporar una capa `Models` para organizar las entidades del sistema.

Actualmente:

- El directorio `backend/models/` no existe.
- Los repositorios existentes devuelven arreglos asociativos.
- No existe una representación tipada y centralizada de las entidades principales del sistema.
- Se necesita establecer una estructura de modelos antes de continuar con la migración de los servicios y repositorios.

La estructura de los modelos debe estar alineada con el esquema real de la base de datos definido en `database/schema.sql`.

## 2. Objetivo

Crear la capa de modelos del backend en:

`backend/models/`

Implementar modelos tipados en PHP 8.1 para las siguientes entidades:

1. `Categoria`
2. `Producto`
3. `Usuario`
4. `Tienda`
5. `InventarioItem`
6. `Cupon`
7. `Pedido`
8. `PedidoDetalle`

Cada modelo debe representar correctamente los campos de su entidad en la base de datos y proporcionar métodos para convertir registros de base de datos en objetos y objetos en arreglos.

También se deben incorporar las pruebas unitarias correspondientes para verificar el mapeo de datos.

## 3. Alcance

Los únicos archivos y directorios que deben crearse o modificarse dentro de este prompt son:

- `backend/models/*.php`
- `backend/bootstrap.php`
- `tests/Unit/Models*Test.php`

Se permite crear los archivos individuales necesarios para implementar los ocho modelos y sus pruebas unitarias.

No se deben modificar los repositorios existentes ni otros componentes del sistema.

## 4. Pasos obligatorios

### Paso 1. Revisar el esquema de la base de datos

Antes de crear los modelos, revisa:

- `database/schema.sql`
- Los repositorios existentes.
- La estructura actual de `backend/`.
- `backend/bootstrap.php`.
- La configuración actual de PHPUnit y las pruebas unitarias existentes.

Identifica las tablas correspondientes a las ocho entidades solicitadas.

Para cada tabla determina:

- Nombre de la tabla.
- Columnas existentes.
- Tipo de dato.
- Clave primaria.
- Claves foráneas.
- Campos obligatorios.
- Campos que admiten valores nulos.
- Valores predeterminados relevantes.

Utiliza también los repositorios para identificar cómo se recuperan actualmente los registros y qué nombres de columnas se utilizan.

**Importante:** no inventes propiedades ni supongas nombres de columnas. Los modelos deben reflejar el esquema real de `database/schema.sql`.

### Paso 2. Crear los ocho modelos

Crea una clase PHP independiente por cada entidad:

| Modelo | Archivo esperado |
|---|---|
| Categoria | `backend/models/Categoria.php` |
| Producto | `backend/models/Producto.php` |
| Usuario | `backend/models/Usuario.php` |
| Tienda | `backend/models/Tienda.php` |
| InventarioItem | `backend/models/InventarioItem.php` |
| Cupon | `backend/models/Cupon.php` |
| Pedido | `backend/models/Pedido.php` |
| PedidoDetalle | `backend/models/PedidoDetalle.php` |

Cada clase debe cumplir los siguientes requisitos:

- Utilizar un constructor con propiedades tipadas.
- Utilizar tipos compatibles con PHP 8.1.
- Representar correctamente los campos de la tabla correspondiente.
- Utilizar propiedades `readonly` cuando sea apropiado y compatible con el diseño de la entidad.
- Respetar los valores nulos definidos en la base de datos.
- Mantener nombres de clases en español, respetando los nombres indicados.
- Mantener una estructura sencilla y coherente con la arquitectura existente.

No agregues métodos de persistencia, consultas SQL ni lógica de negocio a los modelos.

### Paso 3. Implementar los métodos de conversión

Cada modelo debe incorporar los siguientes métodos:

**`fromRow(array $row)`**

Debe:

- Recibir un registro representado mediante un arreglo asociativo.
- Convertir los valores a los tipos definidos por el modelo cuando corresponda.
- Respetar los campos nulos.
- Mapear correctamente los nombres de columnas de la base de datos.
- Crear y devolver una instancia de la clase correspondiente.

**`toArray()`**

Debe:

- Convertir el objeto en un arreglo asociativo.
- Utilizar los nombres de propiedades o columnas establecidos por el esquema.
- Mantener los tipos y valores correspondientes.
- Incluir los campos definidos por el modelo, respetando los valores nulos.

Ambos métodos deben permitir una conversión coherente entre los registros de la base de datos y los objetos PHP.

No agregues transformaciones que alteren el significado de los datos.

### Paso 4. Actualizar backend/bootstrap.php

Actualiza `backend/bootstrap.php` para cargar los ocho modelos.

Consideraciones:

- Respeta el mecanismo de carga actual.
- Utiliza las rutas correctas.
- Evita cargar dos veces las mismas clases.
- Mantén la compatibilidad con los componentes existentes.
- No modifiques la configuración general del backend.

### Paso 5. Crear las pruebas unitarias

Crea las pruebas correspondientes dentro de:

`tests/Unit/`

Utiliza la estructura de nombres:

- `ModelsCategoriaTest.php`
- `ModelsProductoTest.php`
- `ModelsUsuarioTest.php`
- `ModelsTiendaTest.php`
- `ModelsInventarioItemTest.php`
- `ModelsCuponTest.php`
- `ModelsPedidoTest.php`
- `ModelsPedidoDetalleTest.php`

Las pruebas deben verificar, como mínimo:

1. La creación correcta de cada modelo.
2. La conversión de un arreglo asociativo mediante `fromRow()`.
3. La conversión del objeto a un arreglo mediante `toArray()`.
4. El mapeo correcto de los campos.
5. El tratamiento de valores nulos.
6. La conservación de los tipos de datos esperados.

Utiliza filas de ejemplo coherentes con las columnas y tipos reales de `database/schema.sql`.

No utilices datos inventados que contradigan las restricciones del esquema.

Las pruebas deben integrarse con la configuración actual de PHPUnit.

### Paso 6. Mantener separados los modelos y los repositorios

En esta etapa únicamente se deben crear los modelos y sus pruebas.

Por lo tanto:

- No cambies los repositorios existentes.
- No reemplaces los arreglos asociativos que devuelven actualmente.
- No migres consultas SQL.
- No modifiques servicios ni controladores.
- No cambies las rutas existentes.
- No implementes operaciones CRUD dentro de los modelos.

La integración de los modelos con los repositorios se realizará en los siguientes prompts de migración.
