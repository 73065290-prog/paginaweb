## 4. Objetivo

Implementar endpoints JSON que permitan:

- Agregar productos al carrito.
- Actualizar cantidades de productos.
- Quitar productos del carrito.
- Consultar el stock disponible.

Las operaciones deben utilizar `CarritoService` y los componentes existentes de la arquitectura.

El frontend debe consumir estos endpoints mediante `fetch()` desde `frontend/assets/js/ui.js`.

La integración debe ser progresiva: cuando JavaScript esté disponible, se utilizarán las solicitudes asíncronas; cuando no esté disponible, el flujo tradicional debe continuar funcionando.

Todas las respuestas de la API deben utilizar JSON con codificación UTF-8 y códigos HTTP adecuados.

## 7. Seguridad y protección CSRF

Todas las operaciones que modifiquen el carrito deben estar protegidas mediante un token CSRF.

Implementa la protección respetando el sistema de sesiones y seguridad existente.

Requisitos:

- Generar o reutilizar el token CSRF de acuerdo con la implementación actual.
- Entregar el token al frontend de forma segura.
- Enviar el token desde `fetch()` mediante el mecanismo definido en el contrato.
- Validar el token en el backend antes de ejecutar operaciones que modifiquen el carrito.
- Rechazar solicitudes con token ausente o inválido.
- Devolver un código HTTP apropiado y una respuesta JSON uniforme cuando falle la validación.
- No exponer información sensible en las respuestas.
- No desactivar la protección CSRF para facilitar las pruebas.

La consulta de stock, al ser una operación de lectura, no necesita protección CSRF si no modifica el estado del sistema.

No elimines ni reemplaces mecanismos de seguridad existentes.

## 9. Formato de respuestas JSON

Todas las respuestas de los endpoints deben utilizar:

`Content-Type: application/json; charset=utf-8`

Define una estructura uniforme para respuestas exitosas y errores.

Como referencia de estructura, utiliza:

Respuesta exitosa:

```json
{
  "success": true,
  "message": "Operación realizada correctamente",
  "data": {}
}
```

Respuesta de error:

```json
{
  "success": false,
  "message": "No fue posible realizar la operación",
  "errors": []
}
```

Adapta los campos internos a las necesidades reales de cada endpoint.

No devuelvas HTML, mensajes de PHP, trazas de errores ni información de conexión dentro de las respuestas JSON.

Los errores internos deben registrarse de acuerdo con los mecanismos existentes, sin exponer detalles sensibles al cliente.
