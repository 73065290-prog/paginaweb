## Contexto
El proyecto fue analizado con SonarQube (projectKey Pagina_Web_V2). Se reportaron incidencias en `assets/js/admin.js`, `cliente_interfaces/catalogo.php`, `includes/admin/header.php` e `includes/components/cart-line.php`. El prompt original (PROMTS/01) ya fue aplicado en el commit `41a4bde`.

## Objetivo
Dejar en 0 las incidencias indicadas y adjuntar evidencia verificable mediante un reporte de re-escaneo, corrigiendo las debilidades del prompt original: ausencia de ID de regla, falta de criterios de cierre y alcance excedido.

## Pasos obligatorios
1. Identifica el ID de regla de cada incidencia (por ejemplo, `javascript:S7773` para Number.parseFloat/parseInt y `Web:S6853` para labels asociados) y registra la URL del reporte de SonarQube.
2. Verifica mediante búsqueda de texto que no queden `parseInt(` ni `parseFloat(` sin el prefijo `Number.` en `admin.js`.
3. Comprueba que cada input del catálogo, del header de administración y de `cart-line` tenga un label asociado mediante `for` e `id` único. En `cart-line`, los IDs deben ser únicos por cada línea del carrito.
4. Confirma que el comportamiento original se mantenga sin cambios, incluyendo bases numéricas, valores devueltos y cálculos.
5. Ejecuta el re-escaneo mediante `scripts\scan-sonar.bat` y exporta el resultado como evidencia.
