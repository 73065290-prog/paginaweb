## 3. Contexto del proyecto

Actualmente:

- `phpunit.xml` establece `MASS_USE_DB=0`.
- `CatalogoYSqliteLabTest` utiliza SQLite en memoria.
- `MysqlDisponibilidadTest` únicamente comprueba la disponibilidad de MySQL.

Por tanto, todavía no existe una suite que compruebe el funcionamiento real de los repositorios contra MySQL/MariaDB.

## 4. Objetivo

Crear una suite de integración que pruebe los repositorios de categorías, productos, inventario, cupones, pedidos, tiendas y usuarios contra una base de datos MySQL de prueba (`mass_online_test`) independiente del entorno de desarrollo.

Las pruebas deben validar operaciones CRUD, consultas preparadas, manejo de datos especiales y comportamiento real de los repositorios.

## 6. Pasos obligatorios de implementación

### Paso 0. Guardar este prompt
Guarda este prompt en `PROMTS/17.Pruebas-integracion-repositorios-mysql.md` antes de implementar.

### Paso 1. Inspeccionar la configuración actual
- Revisa `phpunit.xml`, `tests/bootstrap.php` y la estructura de `backend/repositories/`.
- Identifica cómo se establecen las conexiones PDO (`Database::pdo()`) y cómo se inyectan las dependencias.
- Revisa las pruebas existentes para evitar duplicaciones o incompatibilidades.
- Identifica las tablas, relaciones y restricciones de `database/schema.sql` necesarias para preparar los datos de prueba.

### Paso 2. Configurar una base de datos exclusiva para pruebas
- Define una base de datos llamada `mass_online_test`.
- Configura la conexión mediante variables de entorno o un archivo local basado en `backend/config/database.test.example.php`.
- Mantén las credenciales fuera del repositorio.
- Asegúrate de que las pruebas nunca puedan conectarse accidentalmente a la base de desarrollo o producción.
- Implementa un mecanismo seguro para crear y preparar la base de pruebas.
- La limpieza debe afectar exclusivamente a `mass_online_test`.
- No elimines ni sobrescribas bases de datos existentes que no sean la base de pruebas autorizada.

Si la configuración no permite demostrar que la conexión apunta exclusivamente a `mass_online_test`, detén las operaciones destructivas y reporta el bloqueo.

### Paso 3. Configurar la suite Integration
- Agrega la suite `Integration` en `phpunit.xml`.
- Haz que se omita automáticamente con `markTestSkipped` cuando MySQL/MariaDB no esté disponible.
- Mantén separadas las pruebas unitarias y las de integración.
- No modifiques el comportamiento de las pruebas existentes para conseguir que la nueva suite pase.

### Paso 4. Crear las pruebas de integración
Implementa pruebas para cada repositorio: categorías, productos, inventario, cupones, pedidos, tiendas y usuarios.

Cada repositorio debe contar, según las operaciones que realmente implemente, con pruebas para:
- Crear, consultar, actualizar y eliminar registros.
- Consultar por identificadores y otros criterios disponibles.
- Validar relaciones y restricciones de base de datos cuando corresponda.
- Ejecutar consultas preparadas con entradas que contengan comillas, apóstrofes y caracteres especiales.

Las pruebas deben comprobar resultados reales en MySQL/MariaDB, no limitarse a verificar que los métodos existan o que no generen excepciones. Usa datos de prueba controlados y no dependas de registros existentes.

### Paso 5. Medir la cobertura
- Mide la cobertura de `backend/repositories`.
- Usa las herramientas de cobertura ya disponibles en el proyecto; no instales dependencias nuevas.
- Si no puede medirse por falta de una extensión o configuración, registra la limitación sin alterar dependencias ni ocultar el resultado.
- Informa el porcentaje obtenido y los archivos no cubiertos, cuando la herramienta lo permita.

### Paso 6. Revisar el resultado
- Comprueba que la suite esté registrada en PHPUnit.
- Verifica que la ejecución no afecte a otras bases de datos.
- Corrige únicamente los problemas relacionados con el alcance autorizado.
- No declares completado ningún repositorio cuya prueba no se haya ejecutado satisfactoriamente.
